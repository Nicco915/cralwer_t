# VEVOR SKU 爬虫 · 项目全貌

> 本文档用于快速建立对项目的整体认识。详细用法见 `README.md`，代理配置见 `说明.md`。

## 一句话定位

基于 Playwright 的 VEVOR SKU 爬虫（Node 20，仅 3 个依赖：`playwright` / `exceljs` / `json-bigint`），以 service 模式常驻运行：从上游 API 拉任务 → 多 Channel 并发抓取 → 回调上报结果 → 单独上传图片。

## 三种运行形态

| 形态 | 入口 | 说明 |
|------|------|------|
| service（生产主形态） | `CRAWLER_MODE=service node bin/run.js` | 常驻拉任务、并发抓取、回调、传图 |
| cli | `node bin/run.js --input SKU_List.xlsx --output ./output` | Excel 批量抓取，断点续传 + 中文翻译（翻译只在 cli 模式） |
| 图片补传 | `node bin/transfer-images.js --dir=...` | 独立脚本，NDJSON state 断点续传，25k 张内存峰值 <1MB |

## Service 模式任务流与并发模型

启动编排（`src/service.js:235-310`）：Pusher → ImageUploader（可选）→ Worker → Poller → 代理池 → 浏览器 → Channels → worker/poller start → 健康检查/心跳/空闲回收/health HTTP。

1. **Poller 拉取**（`src/poller.js`）：每 `pollInterval`（默认 5s）POST 拉任务，仅当 `worker.hasCapacity()`（队列为空且有 idle channel）。任务 id 经 json-bigint 转 BigInt 防精度丢失。无 HTTP 重试，失败等下一 tick。
2. **Worker 入队**（`src/worker.js:93-117`）：`maxQueueSize=50`，`inFlightTaskIds` 去重。
3. **分发**（`worker.js:361-372`）：每 100ms 扫一次，有 idle channel 就 `runTask`（**fire-and-forget，不 await**，这是并发来源）。
4. **抓取**：runTask 先解析 region（未知/禁用 region 直接报错回推，不占通道）→ `channel.busy=true` → `channel.crawl(task)`。
5. **回调**：统一 `pusher.push(result)`（3 次退避重试，落盘审计到 `logs/callbacks/`）；成功后触发图片上传。
6. **收尾**：`busy=false`、写任务事件日志、`channel.onTaskComplete()`（触发轮换检查）。

**并发模型**：单进程单浏览器，N 个 Channel = N 个独立 BrowserContext+Page，`busy` 标志协作式互斥，并发度 = `CRAWLER_CHANNELS`。

## page-crawler 单 SKU 流程

入口 `crawlSingleSku`（`src/page-crawler.js:372-590`）：

1. **URL 构造**：`${baseUrl}/s/${encodeSkuForSearchPath(sku)}`；`-`→`%2D`、`/`→`,`；US 站注入 `cdn_toggle_domain=1` Cookie 绕过 geo 302。
2. **goto 搜索页**（`gotoWithRetry`）：30s 超时，`gotoMaxRetries` 次重试，退避 `[3s,6s,12s]`，最后一次重试前重建 context。错误分类：ERR_TUNNEL/PROXY/CONNECTION_RESET → proxy（不重试）；4xx/5xx → non-retryable；Timeout/其他 net::ERR → retryable。
3. **Cloudflare**：最多等 `cloudflareMaxWait`（45s）；未过 → `not_found + CF_CHALLENGE_UNRESOLVED + dataLayerFailed=true`。
4. **搜索页提取**（`extractProductUrlWithRetry`）：
   - dataLayer fast-path：`result_number===0` → 业务无结果；sku 命中 → 返回 URL；无 dataLayer → 抛 `DATA_LAYER_NEVER_PUSHED`。
   - slow-path：`waitForFunction` 20s 等 sku 出现，超时抛 `DATA_LAYER_MISSING`。
   - HTML 回退：三级正则（sku 附近 goodsUrl → 任意 goodsUrl → 任意 `/p/` href）。
5. **goto 产品页** + CF 二次检查。
6. **SKU 校验**（`extractPageSku`）：dataLayer → HTML 正则 → meta，大小写不敏感；不匹配 → `sku_mismatch`。
7. **字段提取**：h1、`.DM_features_details`、`.DM_product_specification` 等。
8. **图片**：收集 `img.vevorstatic.com` 的 goods_img/original_img，去重，最多 `maxImages`(5) 张，原生 http 下载 30s 超时。
9. **错误出口**：`DATA_LAYER_*` 统一翻译成 `status='not_found' + dataLayerFailed=true`（刻意设计：抛异常会被吞，channel 换 IP 信号会丢）。

## 重试 / 超时 / 自愈分层

| 层 | 机制 |
|----|------|
| Worker | 整体 deadline `taskTimeoutMs`=200s（Promise.race）；`shouldRetryWithNewIp` 换 IP 重试一次；GB/EU/CA 无结果 → US 回退一次 |
| Channel | `consecutiveFailures>=2 && lastFailureWasProxy` 或 `dataLayerFailureCount>=2` → service 轮换代理重建 context；`isHealthy` 5s evaluate 探活；rotateProxy 冷却 30s |
| Page | goto 30s×重试；dataLayer slow-path 20s；CF 45s；固定 sleep 约 10s（2+2+6） |
| Pusher | 3 次退避 `[1s,2s,4s]`；全失败后 worker 降级推 error |
| Service | 健康检查每 30s（browser.isConnected + 逐 channel isHealthy）；`restartBrowser` 崩溃恢复（去抖 + drain 在途任务）；空闲回收 5min 无任务关 context；页面每 20 任务刷新一次；代理池每 5min 刷新 |
| Headed 回退 | timeout/net::ERR 时启动独立 headed 浏览器重跑一次（每次开关整浏览器，成本高） |
| 自适应 stealth | 连续失败切 session 模式换指纹，连续成功切回 channel 固定指纹 |

## 代理体系（静态代理 > Cliproxy 池，二选一）

优先级：**静态代理 `CRAWLER_PROXY` > Cliproxy 池**（`src/service.js` 的 `startProxyPool()`）。静态代理与池凭证同时存在时静态**静默**胜出（无互斥检查）。

### Cliproxy（当前生产方案：一进程一 ASN）

- 控制参数编进代理 username：`user-country-EU-asn-AS577-session-<prefix>-ch1-<nonce>-sticky-30`（`src/cliproxy-pool.js:32-40`）。**nonce 不变 = sticky 期内同一出口 IP；换 nonce = 换 IP**。
- ASN 由部署侧按进程注入 `CLIPROXY_ASN`（VPS 每容器一个、加拿大 Windows 每节点一个），保证跨进程 AS 前缀不相交、结构性不撞 IP。
- `assign()` 重启时从 `cliproxy-assignments.json` 复用旧 nonce，保住 sticky IP；`nextForChannel(force)` 生成新 nonce 换 IP，非 force 有 5min cooldown（静默返回原 URL）。
- **无效 ASN 由供应商静默回落**到其他池，客户端无法感知，只能靠出口校验兜底。
- 出口校验（`src/proxy-exit-check.js`）：手写 HTTP CONNECT + TLS 隧道访问 mayips.com 拿 `{ip, asn, org}`（选 mayips 是因为 ipinfo 会把小 ISP 归并到上游 AS）。**只在 rotateProxy 时校验**（最多 3 个候选，全不匹配仍降级使用最后一个），启动 assign 不校验。

### 多区域（与代理正交）

- `src/region-registry.js`：EU→eur.vevor.com、GB→.co.uk、CA→.ca、US→.com、CN 禁用；`CRAWLER_REGIONS` 可覆盖。
- 区域（爬哪个站）与代理（从哪出口）完全解耦；US 任务靠 cookie 绕过，可跑在非美国出口。
- 可选 `clearCookiesOnRegionSwitch`（默认关）防跨区域 cookie 串扰（不清 localStorage）。

### Stealth 反检测（`src/stealth-profile.js`）

- 确定性指纹档案：种子 = `nodeCode:channelId:sessionIndex`，SHA-256 驱动 LCG 抽 UA/locale/timezone/viewport/内存核数。
- init script 注入：隐藏 webdriver、伪造 plugins/mimeTypes、补 window.chrome、修 permissions.query 等。
- 浏览器启动参数 `--disable-blink-features=AutomationControlled`。

## 配置体系

- 优先级：**CLI flag > 环境变量 > 默认值**。`src/cli.js` 解析（FLAG_MAP / BOOLEAN_FLAGS / envMap 约 60 个变量），默认值集中在 `bin/run.js buildServiceConfig()`。
- `.env` 从 cwd 读取，**不覆盖已有 env**（Docker 下由 compose 注入）。

| 接口 | 端点 | 要点 |
|------|------|------|
| 拉任务 | `POST /renren-api/classify/open/crawler/tasks` | `{nodeCode, nodeToken, limit}`；json-bigint 解析；任务 id 转 BigInt |

## 日志与监控

- `src/logger.js`：NDJSON `{time, level, component, msg, nodeCode, ...}`，BigInt/循环引用安全；stdout + `logs/crawler.jsonl` 双写广播。
- **日志轮转（2026-10 新增）**：`crawler.jsonl` 超过 `CRAWLER_LOG_MAX_SIZE_MB`（默认 50MB）轮转为 `crawler-YYYYMMDD-HHMMSS.jsonl`，保留 `CRAWLER_LOG_RETENTION_DAYS`（默认 7 天）；`logs/callbacks/` 审计目录按同一保留天数清理（Pusher 构造时 + 每小时节流）；`logs/pusher.log` 超 10MB 单份轮转。PM2 托管日志（crawler-combined/out/error-*.log）由 `deployment/windows/setup-pm2-logrotate.ps1` 安装的 pm2-logrotate 轮转（50MB / 保留 7 份 / 每天 0 点，配置后须 `pm2 restart all`）。
- 心跳：每 30s 一条 `component="heartbeat"`；Grafana 告警 `CrawlerNodeHeartbeatMissing`（5min 无心跳 critical）、`CrawlerFailureRateHigh`。
- Health HTTP：`GET /health`（healthPort），浏览器断开返 503；滚动更新和 Blackbox 依赖它。容器 `--hostname crawler-N` 是 Blackbox 探活的硬约束。
- 监控栈：Loki + Promtail + Grafana + Prometheus + Blackbox + node-exporter（`deployment/monitoring/`），仅内网（Tailscale IP）。

## 部署拓扑

- **Linux VPS（生产）**：`node:20-slim` + Chromium 镜像推 GHCR（tag `v*` 触发 CI，**CI 不 SSH 部署**）；VPS 上 8 个独立容器 `hs-sku-crawler-1..8`，`deployment/linux/rolling-update.py vX.Y.Z` 逐台滚动（快照重建、保留 env/端口、/health 150s 等待、不健康回滚中止），每容器注入独立 `CLIPROXY_ASN` 和 `CLIPROXY_SESSION_PREFIX=v0N`。⚠️ CI deploy 会误建重复的 `hs-sku-crawler` 容器，发版后需删除。
- **Windows**：原生 PowerShell（`scripts/deploy/windows/native/deploy.ps1`，PID 管理、每节点 1 channel）或 PM2（`ecosystem.config.js` / `deployment/windows/ecosystem.canada.config.js` 多进程版，每进程独立 `cwd=instances/<nodeCode>`）；国内机器双进程模板 `deployment/windows/ecosystem.local-dual.config.js`（原生 IP 直连无代理、instances/ 隔离、env 显式注入）。bondex 节点用本地 Edge（Edge 自更新交接会致启动瞬时失败，重跑自愈）。
- **transfer-images.js**：流式扫描 + worker 内逐张 readFile；state 文件按 `--dir` sha1 派生；**不要对同一 dir 并发跑两个进程**。

## 已知脆弱点 / 升级雷区

1. **worker deadline 不真正取消 crawl**（`worker.js:253-325`）：超时后 `channel.busy` 已置 false，channel 会被分配新任务 → 两个 crawl 并发共用同一 page，状态互相污染。最危险的并发洞。
2. `status='not_found'` 被复用为信号载体，`dataLayerFailed`/`dataLayerNotFound` 与重试、轮换计数、回调语义耦合极紧，改任一标志位影响全链。
3. `'Page shows no result'` 字符串精确匹配触发区域回退（`worker.js:187`），改文案即静默失效。
4. `CliproxyPool.refresh()` 返回类型与 service 调用方不匹配（返回对象 vs 期望数组），当前因 `undefined > 0 === false` 碰巧无害。
5. 两处代理 URL 未脱敏直接打日志（`service.js:352,537`，其余位置都用 `maskProxyUrl`）。
6. assignments 写盘非原子，崩溃截断 → 下次 load 吞错返回 `{}` → 全 channel 换 nonce → 重启即集体换 IP。
7. refresh 定时器不看 `channel.busy`，可能掐断在途任务（`service.js:348-355`）。
8. 健康轮换调 `nextForChannel` 不带 force，5min cooldown 内会拿到同一 URL 白重建 context。
9. Promtail pipeline 提取字段 `s`/`c` 与 logger 实际输出 `level`/`component` 疑似不匹配，心跳告警可能失效，需核对线上配置。
10. 出口校验强依赖 mayips.com 单点；启动时不校验出口 ASN。
11. 指纹 locale 池以 Europe 为主，与 CA/DE 出口存在指纹矛盾，未按 `CLIPROXY_REGION` 联动。
12. BigInt 任务 id 的 String 化去重 key（`worker.js:62-65`），id 类型混用会让去重静默失效。
13. 单 SKU 时间预算：固定 sleep ~10s + CF 45s×2 + slow-path 20s + goto 重试，最坏情况易顶到 `taskTimeoutMs`=200s，调参需重算预算。
